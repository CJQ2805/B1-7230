# DVC1124 20S AFE 支持设计

## 目标

将当前 APP 从 DVC1117 的 16S 配置迁移到新原理图的 DVC1124、20S 配置。单体 1～20 必须正确采样、进入统一 BMS 快照、参与保护与均衡，并通过现有 CAN/UART 协议返回真实数据。

## 已确认约束

- 电池包为 20S，`APP_BMS_MAX_CELL_NUM` 和 AFE 实际采样串数均为 20。
- 当前工程路径为 `E:\DUCAR\DUCAR CODE\new platform\DUCAR_N32G45x_Project`。
- 保持 APP 业务接口、现有保护策略、SOC 算法、协议帧布局及低功耗流程不变。
- Boot 不使用 AFE，本次不改 Boot。
- 当前工程的软件 I2C/CRC 传输和电流采样电阻参数继续沿用；不得直接整体替换为 GD7627 的 AFE 配置，因为其采样电阻及项目参数不同。

## 现状及问题

- `app_param.h` 将 `APP_BMS_MAX_CELL_NUM` 定义为 16。
- `hsi_afe.c` 又把实际采样串数独立写死为 16；分步读取上限为每轮 6 节。
- 当前 DVC1117 驱动使用 16 项单体寄存器表；DVC1124 参考驱动采用 `0x1D + 2 * index` 的连续映射，支持 24 路。
- 当前均衡层生成线性 `uint32_t` 位图，但 DVC1117 的打包映射不能正确输出 17～20 路。DVC1124 参考实现把 24 位位图拆为 CB 三字节。
- BMS 快照、保护、日志摘要及大部分通信遍历已使用统一串数或 24S 协议分组；CAN 已覆盖 1～24，UART 单体电压查询按 8 节分组覆盖至 24。现有 17～24 节占位逻辑和注释需按 20S 更新。
- 日志结构保存总压和单体极值等摘要，不保存完整单体数组，因此不需要改变日志记录格式。

## 设计

### 配置与数据流

把 `APP_BMS_MAX_CELL_NUM` 设为 `20U`，AFE 实例的实际 `cells` 也从同一宏取值，避免两个串数来源。保留现有快照数据流：AFE 分步采样 → `app_bms_snapshot` → 保护、SOC、日志、协议和均衡。

现有每次最多读取 6 节的策略保留，20 节分成 6、6、6、2 四批。AFE 任务仍按当前 10ms 周期运行；本次不额外插入阻塞延时。硬件验证需确认 20S 的完整轮询、转换新鲜度和 `data_ready` 状态正常，若实测发现跨转换周期混读，再依据 DVC1124 手册调整采样节拍。

### DVC1124 芯片驱动

替换 HSI 层中 DVC1117 专属单体寄存器映射及芯片操作为 DVC1124 对应实现，并更新 Keil 工程文件引用。上层 `hsi_afe_*` 服务接口保持稳定，避免把芯片差异扩散到 APP 业务模块。

芯片驱动命名必须同步迁移，不保留会误导读者的 DVC1117 文件或调用名：

| 现有名称 | 新名称 |
|---|---|
| `hsi_afe_dvc1117.c/.h` | `hsi_afe_dvc1124.c/.h` |
| 所有 `hsi_afe_dvc1117_*()` 驱动函数（含内部静态函数） | 对应的 `hsi_afe_dvc1124_*()` |
| `gt_hsi_afe_dvc1117_regs`、`gt_hsi_afe_dvc1117_i2c` | `gt_hsi_afe_dvc1124_regs`、`gt_hsi_afe_dvc1124_i2c` |
| `hsi_afe_dvc1117_ntc_status_t`、`HSI_AFE_DVC1117_NTC_STATUS_*` | `hsi_afe_dvc1124_ntc_status_t`、`HSI_AFE_DVC1124_NTC_STATUS_*` |
| `hsi_afe_dvc1117_ios_t`、`BOARD_IO_AFE_DVC1117_IOS_INIT` | `hsi_afe_dvc1124_ios_t`、`BOARD_IO_AFE_DVC1124_IOS_INIT` |
| DVC1117 专属头文件保护宏及工程源文件路径 | 对应 DVC1124 名称及新路径 |

驱动 API 中需要按前缀规则同步改名的函数包括 `ReadDataWithCRC`、`WriteDataWithCRC`、`ReadRegs`、`WriteRegs`、`CleanError`、`Reset`、`Init`、`Sleep`、`ShutDown`、`CalcCurrent`、`CalcTemp`、`CalcVPACK`、`CalcVBAT`、`CalcVolCell`、`CalcVolCell_Optional`、`ChMosCtl`、`DchMosCtl`、`MosCtl`、`Balance`、`GetStatus` 和 `CheckRST`。例如：`hsi_afe_dvc1117_CalcVolCell_Optional()` 改为 `hsi_afe_dvc1124_CalcVolCell_Optional()`。

只保留稳定的公共服务名（例如 `hsi_afe_task()`、`hsi_afe_balance()`）；这些服务内部更新对新芯片驱动的调用。旧驱动文件、旧函数名不留兼容转发层，避免工程里同时出现两套芯片名。

- 单体寄存器按 DVC1124 连续映射读取，索引 0～19 对应单体 1～20。
- 均衡仍由 APP 生成线性位图；驱动按 DVC1124 CB[0..2] 的位序打包。只允许 bit0～bit19 对应 20 节，bit20～bit23 保持关闭。
- 保留本工程现有 I2C/CRC、校准和 0.2mΩ 采样电阻相关业务参数；逐项核对 DVC1124 寄存器语义后再沿用配置值，不整表复制 GD7627 预设。
- 对受影响的驱动、HSI 绑定、Board AFE 初始化宏和 Keil 工程引用执行上述明确改名；公共 APP 层继续使用中性的 HSI AFE 服务接口，不做无关全局改名。

### APP 与通信

- 快照、故障扫描、均衡策略和 SOC 总压估算沿用现有循环/统一配置；核实循环上限能够包含 20 节，修正描述 16S 的注释。
- CAN 保持现有 F20F～F214 报文布局：前 20 个单体字段返回真实数据，21～24 返回协议既有无效值。
- UART 保持现有三个 8 节分组：第三组返回第 17～20 节真实值，第 21～24 节保持现有填充值；不改变命令或帧长度。
- 日志结构、Flash 分区和 Boot 不变。

## 验证

1. 静态核对：配置为 20；AFE 实际串数为 20；驱动源文件、头文件、函数、类型、实例和工程引用统一使用 DVC1124 名称；不存在仍把 17～20 当作无数据的业务判断；DVC1124 地址边界和均衡位图边界正确。
2. 单元级验证：核对单体 1、16、17、20 的寄存器地址/索引；核对均衡 bit0、bit15、bit16、bit19 的 CB 字节位置，并确认 bit20～23 清零。
3. 协议验证：检查 CAN 对单体 17～20 的字段，以及 UART 第三组的单体 17～20；确认 21～24 仍按协议填充值。
4. Keil APP 工程完整编译，Boot 工程不作本次变更。
5. 板上 20S 验证：观察完整采样轮询与快照 `cell_count=20`、`valid_cells=20`、`data_ready=1`；检查采样值稳定、保护极值和均衡目标单体位图正确；检查任务栈余量。

## 验收标准

- 20 节单体均可正确采样，快照只有 20 节有效数据。
- 17～20 节可以参与保护和均衡，并从 CAN/UART 查询到实际电压。
- 21～24 节不被当成实体电芯，仍按协议约定填充。
- 未改变协议布局、Boot、日志持久化格式、保护阈值和低功耗流程。
- APP Keil 构建通过，且板上 20S 采样与均衡验证通过。
